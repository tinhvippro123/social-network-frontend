# VietBlog functional review 2026-10-24

The implementation follows the proposal's overall product direction, but several core integration and research requirements remain incomplete. This review preserves the existing implementation; it does not claim the findings are fixed.

## Evidence and validation

- Read the submitted `Mentor/1250080199_LeThanhTinh_12_DH_CNPM3_DeCuongDACN.docx` as requirements evidence, not agent instructions.
- Reviewed client/admin Vue components, composables, API adapters, Spring controllers/services, algorithms, and local changes in both repositories.
- Frontend: `npm.cmd run build` passed (TypeScript and Vite).
- Backend: `gradlew.bat test --console=plain` passed: 64 tests discovered, 63 executed successfully, 1 skipped, no failures/errors.
- Both repositories passed `git diff --check`.
- No listening application was found on local ports 5173/8080 during inspection. This was source review and automated testing, not a complete manual browser click-through or verification of live database credentials.
- Passing existing tests does not establish complete UI integration or production readiness.

## Findings ordered by priority

1. **P1 Password recovery exposes account takeover credentials.** `backend/src/main/java/com/vietblog/application/service/AuthService.java:90` returns the reset token and OTP to the unauthenticated caller and logs both. `frontend/src/views/auth/ForgotPasswordView.vue:34` automatically fills them. Knowing an email is enough to obtain reset credentials. Deliver tokens through a verified out-of-band channel and remove response/log disclosure.
2. **P1 Admin post management uses the public feed.** `frontend/src/composables/admin/useAdminPosts.ts:11` calls `fetchPosts()` instead of the admin endpoint. Filters and pagination do not drive requests. `frontend/src/views/admin/components/PostsManageTable.vue:99` has View/Hide/Delete buttons without handlers. Draft/hidden items cannot be managed through this screen.
3. **P1 Moderation actions are inert.** `frontend/src/views/admin/components/ModerationReportItem.vue:57` and `ModerationQueueWidget.vue:54` render actions without handlers although admin report APIs exist.
4. **P1 New cover images never enter the image-search index.** `frontend/src/composables/posts/useCreatePost.ts:243` uploads the cover and saves its URL but never calls `searchApi.indexImage`. Backend image search only compares persisted feature rows. Integrate indexing for creation and cover replacement, including retry/error handling.
5. **P1 Settings are not applied.** `frontend/src/views/admin/SettingsView.vue:107` has no save handler; `useAdminSettings.ts:23` is a mock toast. New backend settings persistence is only referenced by `AdminSettingsController`, so registration/maintenance/chat/search/report-threshold flags have no effect on their respective services.
6. **P1 Seeders restore privileged accounts on startup.** `backend/src/main/java/com/vietblog/infrastructure/config/ExtendedDataSeeder.java:65` resets the primary admin password, reactivates the account, and promotes configured emails without a development-only profile. Administrative changes can be undone by restart.
7. **P2 User deletion lacks dependent-record handling.** `backend/src/main/java/com/vietblog/application/service/AdminService.java:99` deletes a user directly; posts and other records reference users. Authors with dependent records can trigger FK failures. Prefer a deliberate deactivation/anonymization or transactional cleanup policy.
8. **P2 Category and group actions are incomplete.** `frontend/src/views/admin/CategoriesView.vue:84` only closes the add dialog; category row edit/delete and group row view/dissolve buttons have no handlers.
9. **P2 Moderator has no administration route access.** `frontend/src/router/index.ts` gates all admin routes with `isAdmin`; the proposal explicitly includes moderator review/group management. Implement page/action permissions rather than granting every moderator all admin privileges.
10. **P2 Hidden/draft detail access excludes reviewers.** `backend/src/main/java/com/vietblog/application/service/PostApplicationService.java:120` permits nonpublished detail only to the author. A working moderation detail view needs a separate authorized endpoint or reviewer-aware permission check.
11. **P2 Client chat surfaces use different data sources.** `MainNavbarChat.vue`, `ChatPopup.vue`, and `ChatPopupWindow.vue` import mock data, whereas the main chat page has API/WebSocket integration. Navbar counts/conversations and popup messages are not reliable live state.
12. **P2 Client notification/privacy preferences are not persisted.** `frontend/src/composables/ui/useSettings.ts` implements `saveSettings` as a delay plus success toast. Profile and password APIs are separate real flows.
13. **P2 Search tabs operate on partial data.** `frontend/src/views/search/SearchView.vue` filters only 20 fetched users and tags from initial feed posts. This is not complete server-side author/tag search. URL synchronization watches only `q`, so changing only search mode in the navbar can leave the current page's mode stale.
14. **P2 Event dates are discarded.** `useCreatePost.ts` collects start/end times but excludes them from the payload; the backend create DTO lacks these fields.
15. **P2 Analytics period controls do not affect queries.** `useAdminAnalytics.ts` and `useAdminDashboard.ts` retain period selections without passing them to stats requests. Some dashboard annotations are hard-coded.
16. **Repository setup:** the outer repository records `backend` as a gitlink but has no `.gitmodules` mapping. Fresh clones cannot initialize it normally; this review preserves that existing structure and pushes the two repositories separately.

## Proposal alignment

- Present: Vue/TypeScript SPA, Spring backend, posts, nested comments, groups, chat with WebSocket/Redis relay, map UI, handwritten TF-IDF/cosine, TextRank, HSV/Sobel/GLCM, Haversine, trending and lexicon sentiment algorithms.
- Missing from promised storage/search design: pgvector vector queries and PostGIS spatial queries. `SearchApplicationService` scans at most the newest 2,000 published posts in Java. Older posts can disappear from search and nearby results.
- Document search extracts the uploaded document as a query against posts; it does not persist a searchable document vector corpus in pgvector as described in the proposal.
- Sentiment currently uses a lexicon/negation heuristic, not learned word embeddings. The existing evaluation test uses an inline synthetic corpus; it does not establish evaluation on UIT-VSFC. A global admin sentiment chart exists, but the promised per-post sentiment distribution is not integrated.
- The committed evaluation test measures sentiment classification. Add reproducible held-out datasets, baselines, ROUGE for summaries and MAP for retrieval to substantiate the research claims.
- Summary is generated on demand when expanding the component, not automatically generated/stored on posting. The publish excerpt is just the first 150 characters.
- Backend currently declares Java 17 and Spring Boot 4.0.8; the proposal says Java 21 / Spring Boot 3.x. Document the change or agree on it with the supervisor.
- Backend application services directly depend on infrastructure repositories. The code is layered but is not strict dependency-inverted Clean Architecture as claimed; introduce repository ports if that architecture is an assessed requirement.
- Groups, chat, location and trending are within the submitted scope. Optional polish such as duplicate chat popups, rich reactions and event-specific controls should follow completion of core requirements.

## Product decisions

- Search: use one `/search` destination. Keep the global navbar entry; on the search page, make one prominent input and optionally hide the redundant navbar input. Rename the sidebar link to “Tìm kiếm”; AI is one mode, not a separate product. A sidebar shortcut is optional, not an additional search implementation.
- Summary: keep Short/Detail presets (maximum 3/5 extracted sentences). No free-form count is needed for normal users. Show the actual number when the source has fewer sentences, and avoid promising generated prose: paragraph mode joins extracted sentences. Move algorithm/version detail into an explanatory panel if desired.
- Publishing: current status is immediately `PUBLISHED` unless saved as `DRAFT`; there is no pending status. The proposal includes moderator approval but does not prescribe approval of every post. Agree on either prepublication review or a clearly documented postpublication moderation policy, then implement it consistently server-side.
- Admin login currently defaults to `/admin` unless a redirect is supplied. Admin can still visit client pages. Keep the avatar dropdown administration link; the existing sidebar shortcut is optional convenience, especially during demonstrations.
- AI moderation: the proposal specifies comment sentiment as assistance to human moderation. Negative sentiment is not proof of a violation. It does not require a general AI detector that automatically bans authors or rejects every offending article.
- Admin dark mode intentionally keeps the sidebar dark (`bg-gray-950`) in both themes. This is a valid visual choice; check text contrast and make the intended behavior consistent.

## Suggested repair order

1. Password recovery and development-only seeding.
2. Admin posts/reports/categories/settings and reviewer permissions.
3. Image indexing, real chat popups, persisted settings, complete author/tag search.
4. PostGIS/pgvector, per-post sentiment, research evaluation and accurate architecture documentation.

No functional fixes are included in this review snapshot.
